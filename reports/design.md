# 온지붕 — 설계 (2026-10-05 방향 정리)

> 같은 날 방향을 한 번 더 바꿨다: **사람 검수 없이, 정답이 필요 없는 구조로 AI를 배치한다.** 판독 도구(`labeling/`) 제작은 취소했고 만들어 둔 파일은 쓰지 않는다. AI가 매긴 판독·라벨 결과(`reports/stage1_5.md`, `reports/text_classifier.md`)는 검증 근거로 쓰지 않는다. 관련 문서: `roof_normalization.md`(지붕 기재 전수 정규화), `exp_post2010.md`(연식 착시 검사), `change_detection.md`(과거 영상 변화탐지), `priority_score.md`(우선순위 점수).

## 한 줄 정의

AI가 건축물대장의 숨은 슬레이트 기록을 찾고(텍스트), 먼저 볼 순서를 정하고(영상·점수), 담당자의 현장 확인으로 계속 배우는(순환) 건물 단위 확인 도구.

"AI가 지붕을 판정한다"가 아니다. 지붕이 실제로 슬레이트인지는 사람이 확인하고, AI는 그 확인을 덜 헛걸음하게 만든다.

## AI·분석 요소와 현재 근거

| 요소 | 하는 일 | 현재 근거 | 상태 |

## 현장 확인 → 재학습 순환

```
대장 텍스트 분류(①) ─┐
영상 분류 점수(④) ───┼→ 후보 목록·우선순위(③) → 담당자 화면(건물 클릭)
이상 탐지(②) ────────┘                              │
        ▲                                            ▼
        │                               현장 확인 버튼
        │                 [슬레이트 맞음] [아님(개량)] [철거됨] [확인 불가]
        │                                            │
        └──── 재학습(주기적) ◀── 확인 기록 저장 ◀─────┘
```

**저장하는 것** (건물 1건 확인 = 1행)
- 건물 내부 ID(GIS건물통합식별번호), 판정 4종, 확인 일시, 확인 방법(현장 방문 / 전화 / 영상), 확인자 구분(읍면동 코드까지만)
- 소유자·거주자 이름, 연락처, 상세 주소는 저장하지 않는다.

**재학습에 쓰는 방식**
- 영상 분류(④): 확인 기록을 정답으로 대장 라벨(약한 라벨)을 대체한다. 지금은 정답이 0건이라 성능이 낮고, 확인이 쌓일수록 학습·평가 양쪽이 개선되는 구조다. 재학습 때마다 확인 기록의 일부를 떼어 두고 그 표본으로만 성능을 다시 잰다.
- 텍스트 분류(①): "대장=슬레이트인데 현장=아님"이 특정 표기(예: `스레트기와`)에 몰리는지 집계해 규칙을 고친다.
- 우선순위(③): 확인 결과 "맞음" 비율이 높은 조건(연대·지역·표기)에 가중치를 더 준다. 가중치 변경 이력은 남긴다.

**재학습 조건(안)**: 새 확인 기록이 200건 쌓일 때마다, 또는 분기 1회. 재학습 전후 성능을 같은 평가 표본으로 비교해 나빠지면 이전 모델을 유지한다.

**아직 모르는 것**: 확인 기록이 몇 건 쌓여야 영상 분류가 쓸 만해지는지는 알 수 없다. 0.24m급 영상의 판독 한계(AI 예비 판독에서 판독불가 11.3%, 도색·덧씌움 슬레이트 구분 불가) 때문에 상한이 낮을 수 있다.

## 화면 (본선용)

- **건물 지도(3D)**: 슬레이트 주택이 몰린 읍·면 8곳의 건물 도형을 높이만큼 세워 보여주고, 건물을 클릭하면 대장 지붕 기재·사용승인연도·면적·매칭 방식·이상 표시가 뜬다. 3D는 보여주는 수단이며 판정 기능이 아니다.
  - 높이: GIS건물통합정보의 높이 → 없으면 지상층수 × 3m → 둘 다 없으면 3m. 추정한 건물은 패널에 "높이 추정"으로 표시.
  - 색 3종: 대장 슬레이트 주택 / 그 외 주택 / 그 밖(비주택·대장 미연결).
- **찾아가는 신청 목록**: 읍면동 담당자용 우선순위 목록 (본선 전 구현).
- **현장 확인 버튼**: 위 순환의 입력 (본선 전 구현).
