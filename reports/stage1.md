## 4. C — 표제부 ↔ 건물 폴리곤 조인

- **대장 PK로는 조인 불가**: `mgmBldrgstPk` 와 GIS `건축물ID(A19)` 가 숫자로 같은 쌍이 21,109건 있으나 그중 필지까지 일치하는 것은 1.1% → 서로 다른 번호 체계. 
- **PNU(필지)로 조인**: 표제부의 시군구+법정동+대지구분+본번+부번으로 19자리 PNU 구성(구성 불가 17건).

| 구분 | 필지(PNU) 매칭 | 건물(동) 단위 매칭 |
|---|---|---|
| 표제부 전체 49,728 | 44,305 (89.1%) | 40,057 (80.6%) |
| 주택류 26,645 | 23,938 (89.8%) | 85.0% |
| **슬레이트 주택 6,189** | 5,055 (81.7%) | **4,739 (76.6%)** |

- 동 단위 배정 방법(슬레이트 주택): 필지에 대장 1건·폴리곤 1개 → 1,382동 / 같은 필지 안에서 건축면적이 가장 가까운 폴리곤(상대오차 20% 이내, 1:1) → 3,357동.
- **매칭 안 된 슬레이트 주택 1,450동**: 해당 필지에 폴리곤이 아예 없음 1,134동 + 필지는 있으나 어느 동인지 특정 불가 316동.
  - 필지에 건물 도형이 없는 1,134동은 "이미 철거됐는데 대장이 남아 있음" 또는 "GIS 도형 누락" 중 하나일 수 있음. 어느 쪽인지는 미확인(현장·영상 확인 필요).
- 반대 방향: 폴리곤 78,355동 중 18,429동(23.5%)은 같은 필지의 표제부가 없음 → 무허가·미등재 건축물 또는 집합건축물 등. 이들 지붕은 대장으로 알 수 없음.
- 한계: 면적 기반 배정은 같은 필지에 비슷한 크기의 건물이 여럿이면 틀릴 수 있음(오배정률 미확인).

**해석 — 과장 없이**
- 무작위(0.5)보다는 낫지만 **현 상태로는 후보 선별에 쓰기 어려운 약한 성능**.
- 라벨이 "대장 기재"라서 정답이 아님(약한 라벨). `disagree_register_slate_model_not.png` 를 눈으로 보면 대장은 슬레이트인데 영상에는 새 칼라강판 지붕, 옥상 방수된 평지붕, 태양광 올린 지붕, 빈 터가 여럿 보임 → **대장 미갱신이 실제로 적지 않아 보이며**, 이것이 라벨 노이즈로 작용해 성능 상한을 낮춤. (건수는 세지 않았음 — 육안 인상이며 미검증)
- 반대 그리드(`disagree_register_not_model_slate.png`, 숨은 슬레이트 후보)는 육안으로 슬레이트라고 보기 어려운 것이 다수 → **현재 모델의 "숨은 슬레이트" 판정은 근거 자료로 쓰기에 신뢰도가 부족**.
- 예측 확률이 0 또는 1에 몰림(982개 중 0.01~0.99 사이는 773개, 양 끝 209개): 특징 1,280차원에 학습 표본 약 785개라 과적합. 확률값 자체를 "확신도"로 해석하면 안 됨.
- 하이퍼파라미터(C, 모델, 줌)는 한 번 정한 값 그대로이며 성능을 보고 고르지 않았음.

## 6. 한계

1. **색칠·덧씌운 슬레이트**: 도색했거나 칼라강판을 덧씌운 슬레이트는 위에서 보면 강판 지붕과 구분되지 않음. 대장 텍스트에 강판·판넬이 병기된 슬레이트 주택만 42동.
2. **그림자·해상도**: 줌 19(약 0.24m/px)로는 슬레이트 골(파형)이 보이지 않음. 색·질감에만 의존. 나무·그림자에 가린 지붕, 영상 촬영 시점(미확인)과 대장 시점 차이도 오차 요인.
3. **라벨 노이즈**: 대장 기재 = 약한 라벨. 미갱신(개량·철거 후 그대로), 혼합 표기(일부만 슬레이트), 필지 내 동 오배정이 모두 섞여 있음. 현장 검증 라벨이 한 건도 없어 모델의 실제 정확도는 **미확인**.
4. **무허가·미등재 건축물 누락**: 대장에 없는 건물은 6,189동에 포함되지 않음. 경산 폴리곤의 23.5%가 표제부 없는 필지에 있음. 축사·창고 등 비주택 슬레이트(대장 기준 약 3,054건)도 이번 집계 밖.
5. **지역 일반화**: 분류 시험은 자인면 한 곳. 다른 읍면·동 지역에 대한 성능은 미확인.
6. **연도 품질**: 사용승인연도는 연도만 기재되거나 1900년대 초로 적힌 건이 많아 노후도 지표로 쓸 때 보정 필요.
7. **지원 물량 95동**: 외부 확인 전 수치.

**지침과 달라진 점**
- Python 3.11 대신 3.14 (PC에 3.14만 설치됨).
- 로지스틱 회귀·교차검증·지표는 scikit-learn 대신 `src/mlutil.py` 의 자체 구현(torch/numpy) 사용. 이 PC의 Windows 애플리케이션 제어 정책이 scikit-learn DLL 로드를 차단했기 때문. 목적함수는 sklearn `LogisticRegression(C=0.1)` 과 동일하며 합성 데이터로 동작을 확인함.
- 브이월드 키는 다른 프로젝트(dasel)용으로 발급된 키를 사용 중(등록 URL이 localhost가 아님). 2단계 웹 데모 전에는 이 프로젝트용 키를 새로 발급해야 함.
